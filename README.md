# AlertForge — *From Attack to Alert*

A free, open platform built around one idea every security practitioner lives by:
the chain from an **attack**, to the **trace it leaves**, to the **rule that catches it**,
to the **fix** — made explorable, teachable, and reusable.

> It **explains** attacks; it never **runs** them. A comprehension and knowledge tool,
> safe and legal by design.

## What's here (Sprint 0)

This is the foundation: the content schema and the first technique. The web UI
comes in Sprint 1.

```
alertforge/
├── data/
│   ├── schema.technique.json     # the contract every technique conforms to
│   ├── techniques/
│   │   └── kerberoasting.json     # the first technique
│   └── index.json                 # generated by the validator — do not hand-edit
├── scripts/
│   └── validate-content.mjs       # validates techniques + regenerates index.json
└── package.json
```

## How a technique works

Each technique is **one JSON file** — data, not code. It has six parts that map to
the six panels the UI will show:

1. **attack** — what the adversary does, and why
2. **artifact** — the exact trace it leaves in the logs
3. **detection** — the rule that catches it, annotated line-by-line
4. **ATT&CK mapping** — the official technique ID + tactic
5. **falsePositives** — benign activity that trips the same rule
6. **mitigation** — how the underlying weakness is fixed

To add a technique: copy an existing file in `data/techniques/`, edit the fields,
and run the validator. No code changes needed.

## Develop

```bash
# Install dev dependencies (the schema validator)
bun install

# Validate all techniques and regenerate data/index.json
bun run validate:content
```

The validator fails if any technique breaks the schema — so bad content never
gets merged.

## Content integrity

- Every technique cites its ATT&CK ID and links to attack.mitre.org.
- Detection rules are real and attributed, with the source licence noted.
- No fabricated statistics or invented tools.
- Commands shown are illustrative / lab-only.
